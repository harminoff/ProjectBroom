# Project Broom static GZDoom mod

## Starting Project Broom

Double-click `ProjectBroom.exe` in the project root. The launcher chooses a new
positive random Brogue game seed, prepares the matching 40-depth campaign, and
opens the Project Broom title menu. Choose **New Game** to enter depth 1. The first
launch of a seed takes longer because Brogue must generate every depth and the
map compiler must build its PK3; generated seeds are reused when their manifest
still matches. While this happens, the launcher displays the live preparation
phase and an animated progress indicator for Brogue generation, 3D map
compilation, integrity verification, and GZDoom startup.

Developers can run `ProjectBroom.exe --seed 1` to exercise the same menu with a
repeatable seed. Preparation failures are recorded in
`artifacts/launcher-last.log`. Load/save is not offered yet because restoring
only GZDoom state without the authoritative Brogue simulation would be unsafe.

The title and pause menu use a dedicated 640x400 layout and the opaque
`BrogueMenu` bitmap font generated by `tools/generate-menu-font.ps1`. This
keeps the original Brogue glyph shapes while avoiding filtered, low-alpha menu
text. The static mod's `GAMEINFO` names the running frontend `Project Broom`, so
the development IWAD name is not shown in the player-facing window title.

This directory contains the runtime slice shared by generated Brogue maps.
Generated UDMF maps and their `MAPINFO` are packaged separately by
`tools/mapcompiler/compile.py`.

The static mod also vendors [UltimateClassicMinimap](https://github.com/Lewisk3/UltimateClassicMinimap)
at upstream commit `0c690b839b333da1823b935e9d6db7fa9379cfd9`. It is loaded
from `ZSCRIPT` alongside the Brogue world handler. It remains available as
optional development tooling, but the source-bridge launcher hides it. The
normal HUD draws a rectangular 79x29 ASCII minimap from Brogue's final
`getCellAppearance()` glyph, foreground, background, discovery, visibility,
lighting, item, and creature output and never enables `ucm_mapshowall`.
Use the `Minimap Controls` section under Options > Customize Controls for
zoom, pan, full-size, and visibility controls.

The map projection validates the 79x29 Brogue cell grid and implements
hub-safe upstairs/downstairs travel. UDMF emits one physical sector per
traversable or dynamic-door cell and blocking perimeter walls for other solid
cells; the full raw cell state remains in the JSON snapshot. The live source
bridge now supplies authoritative items, monsters, combat, turn scheduling,
prompts, and game outcomes; the generated-map-only path remains a topology
tool rather than an alternate simulation.

The source bridge supplies player statistics, visible creatures and items,
messages, map knowledge, and inventory data to the Brogue-framed HUD. The UI
and map fonts are deterministic bitmap extractions from Brogue CE's pinned
`bin/assets/tiles.png`; GZDoom renders them with nearest-neighbor integer
scaling. The fullscreen map uses a separate 32x58 extraction for clear enlarged
glyphs; the minimap retains its compact 5x8 font. Both retain the upstream
Brogue CE font provenance and licensing. Press
`I` for the modal two-pane inventory. Arrow keys, mouse wheel, or Brogue's
inventory letters select items; `Enter`/`U` uses food, potions, scrolls, and
charms, `E` equips or removes, `D` drops, and `T` enters the existing
bridge-authoritative throw targeting flow. Hazardous consumption prompts and
identify/enchant item selection are returned by the bridge and shown in the
inventory. Opening, navigating, and closing the inventory do not advance a
Brogue turn.

Brogue's movement and combat warnings are also forwarded verbatim. Entering a
chasm, flame, dangerous gas, or a known pressure plate—and other actions that
call Brogue's own confirmation routine—pause behind a `Y`/`N` confirmation
without advancing the bridge revision or turn.

The generated maps use original Project Broom artwork under `graphics/` for cave
rock, damp earth, worked basalt, doors, water, lava, moss, bridges, and chasm
presentation. Material roles come from Brogue's authoritative terrain layers,
and one coherent palette is used across each semantic region.
Ordinary surface layers such as grass and lichen tint the underlying floor
instead of replacing its geology; bridges remain explicit deck materials.
Grass, fungus, luminous fungus, foliage, and dead vegetation also produce
non-interactive sprite props. Dense foliage appears on every eligible Brogue
cell; lighter surface types remain sparse. Their type and placement are derived
deterministically from Brogue's surface layer, game seed, depth, and cell
coordinate; they never affect collision or simulation. Use
`scripts/launch-seed.ps1 -NoSound` on systems whose OpenAL device is not
available during development.

Water, sludge, lava, and waterfall materials use presentation-only GZDoom
warping declared in the root `ANIMDEFS`. Brogue CE remains authoritative for
their identity, movement rules, and runtime state.

For parity testing, run `scripts\launch-comparison.cmd -Seed 1`. This opens an
exact-commit graphical Brogue build beside GZDoom. Numpad 1-9 supplies the same
eight-way movement intent to both simulations and Numpad 5 waits. See
`docs/brogue-gzdoom-comparison-mode.md` for the test boundary and controls.

# Doors and stairs

Stairs use static OBJ presentation models through `MODELDEF`; invisible logical
actors at the exact Brogue coordinates still own travel interaction. Closed
doors are generated sectors and are opened/closed only after the source bridge
reports an authoritative Brogue terrain change. Pressing Use does not invoke a
separate Doom door rule; move toward a door as you would in Brogue.
